## 1. 当前状态与裁定范围

Part A 已完成静态与功能核验，但其 live 触发和逐臂统计仍为 `BLOCKED`。Part B 的数据字典、质量/延迟规范和离线分析工具已交付；其报告总体状态为 `CONDITIONAL`，因为账号作用域、并发、生产延迟和真实实验臂等采集仍未落地。因此，“Part B 已交付”不等于跨账号/网关验证或主线实验已完成。

本协调裁定解决 Part A 报告列出的四项决策，并明确下一步唯一实现者。裁定不替代版本化实验契约，也不改变代码中的默认值。

## 2. 四项协调裁定

### 2.1 默认行为与 NO-GO：采用方案乙

采用计划 §3.2 的**方案乙：隔离未获准行为**。

- 在隔离实验契约及必要审批完成前，不扩大真实用户行为暴露，不发起可能改变真实用户行为的 live 实验。
- 不修改代码默认值。目标采样环境须通过显式配置验证实际消费值；无法确认目标环境配置与回滚路径时，只允许静态检查和隔离夹具测试。
- `low_yield_latch` 是 A 的行为因子。实验契约外及 Baseline 臂显式关闭；只有隔离矩阵中预注册的 A-on 臂可开启。
- `message_shape_diagnosis` 按 B 因子处理：契约外及 Baseline/A-only 臂显式关闭；仅 B-only/A+B 隔离臂按预注册条件开启。开启它不构成生产启用授权。
- Rescue 不进入四臂常规矩阵，只能作为单独、受控的安全演练，并记录独立批准与停止条件。

### 2.2 §3.3 混杂控制：`cache_aware_compaction=false`

四个常规臂统一固定 `cache_aware_compaction=false`，不把该既有特性并入 A 因子。Agent C 负责修正条件注册表并添加逐臂配置消费断言；在断言证明四臂实际值一致前，不得运行矩阵或将结果归因于 A/B。

| 常规臂 | `low_yield_latch` | `message_shape_diagnosis` | `cache_aware_compaction` |
|---|---:|---:|---:|
| Baseline | false | false | false |
| A-only | true | false | false |
| B-only | false | true | false |
| A+B | true | true | false |

如需评估 `cache_aware_compaction`，另立因子与实验契约；不得事后将它纳入本轮 A 效果解释。

### 2.3 `compact_ratio=0.05`：注册为独立功能触发 profile

将 `agent.compact_ratio=0.05` 注册为**实验专用的功能触发 profile**，其目的仅为以可负担样本验证维护路径能否触发以及事件链路是否完整。该 profile 与生产代表性 profile 分开运行、分开汇报；不得混合样本或用其估算生产收益。

- 功能触发 profile 的四个常规臂使用相同 `compact_ratio=0.05`，并固定 `visible_window_tokens=16000`；逐臂记录配置快照和实际消费值。
- 生产代表性 profile 使用目标环境的实际生产阈值，不为凑触发而调低；如果样本未触发，记录为未观测，不解释为路径无效。
- 任何 `0.05` 下的结果只支持“功能可达/机制可观察”，不支持生产触发频率、收益或安全性外推。
- Agent C 在 registry 中显式区分 profile 与实验变量；Agent A 复核触发配方和消费证据。不得修改生产默认阈值。

### 2.4 Sidecar-only 事件：纳入成员记录的可选诊断投影

将以下三个已有 receipt 诊断值纳入成员记录，作为可选字段投影，以支持按样本核验维护状态与触发结果：

- `MaintenanceState`（序列化字段名由 C 按现有命名约定确定）；
- `HeadroomTokens`；
- `ReductionRatio`。

它们仅用于观测与归因，不新增行为消费，不建立第二事实源，也不扩展到其他 sidecar 字段。缺失值必须保持为“未观测”，不得补零或推断。兼容性、omitempty/缺失语义及与 Part B 数据字典的合并由 C 在实现前写入接口变更说明。

**唯一实现者：Agent C**，在成员记录/publisher 接线。Agent A 负责确认 receipt 字段的语义与生成时点；Agent B 负责将字段纳入数据字典、缺失/unknown 处理及隐私审阅。A、B 不直接修改 C 的写集。实现后由 A/B 交叉复核记录映射及分析口径。

## 3. 执行顺序与责任

1. **C：冻结契约与修正矩阵。** 建立版本化 `experiment-contract.yaml`（或等价记录），记录基线快照、profile、逐臂开关、token 配置、有效样本、指标与隐私口径、预算、停止/回滚规则；落实 `cache_aware_compaction=false` 和逐臂断言。
2. **A：解除静态/隔离验证阻塞。** 在冻结契约下复核行为因子边界、两个触发 profile、配置消费和维护事件语义；未获 live 采样前不发起真实请求。
3. **B：合并并锁定观测契约。** 将 Part B 已交付的数据字典与本裁定的三个诊断字段、C 的采集字段对齐；保留其 `CONDITIONAL` 边界，直到真实采集与跨账号/网关条件有证据。
4. **C：落实唯一代码接线并验证。** 先提交字段/registry 接口变更，再实现记录投影及测试；完成静态验证、隔离 pilot 和质量/隐私复核后，另行提交 live pilot 预算与批准请求。
5. **协调者：单独批准 live pilot。** 只有契约冻结、配置消费断言通过、字段与数据检查通过、隔离与回滚可用、预算及凭证范围明确后，才可书面批准有限 live pilot。pilot 不是正式矩阵或灰度批准。

## 4. 解除阻塞的判定

本文件完成了 Part A 报告要求协调者裁定的四项内容，但**不自动将 Part A 的整体状态改为 PASS，也不授权 live 实验**。A 可在以上裁定下继续静态和隔离工作；只有版本化契约及配置证据落地后，才能解除“缺少书面裁定/冻结契约”这一阻塞。真实请求仍受第 3 节第 5 步的独立门禁约束。

Part B 可记录为“交付完成、验证条件仍未满足”：其文档和离线分析交付已完成；跨账号/网关覆盖、并发及生产延迟采集仍须由后续实现和采样补齐。除非相应证据实际取得，不得将状态提升为全面 `PASS`，也不得宣称主线优化验证闭环。

## 5. 不在本裁定授权范围内

- 修改生产默认开关、默认 `compact_ratio` 或全量部署配置；
- 扩大灰度、对真实用户执行未获单独批准的行为实验；
- 把功能触发 profile 的结果外推为生产收益或跨账号/网关结论；

- 将 `cache_aware_compaction`、Rescue 或其他新增因子混入本轮四臂归因。
